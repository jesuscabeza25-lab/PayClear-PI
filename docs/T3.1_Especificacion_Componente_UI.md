# Especificación del componente `ExpenseCardPanel` (Tarea T-3.1)

Este documento recoge el diseño visual, las propiedades y el contrato de eventos de `ExpenseCardPanel` para que tanto Frontend (`T-3.2` y `T-3.3`) como Backend (`T-3.4`) puedan trabajar sobre una misma base sin pisarse código.

---

## 1. Qué hace el componente y de qué clase hereda

* **Clase y paquete:** `com.payclear.ui.components.ExpenseCardPanel`
* **Herencia:** Extiende directamente de `javax.swing.JPanel` e implementa `java.io.Serializable` (jerarquía estándar de Java Swing: `Object -> Component -> Container -> JComponent -> JPanel -> ExpenseCardPanel`).
* **Objetivo en PayClear:** Es la tarjeta visual reutilizable donde se muestra cada gasto compartido dentro de un grupo (concepto, importe, quién pagó, fecha, categoría y si está saldado o pendiente). Solo se encarga de pintar los datos y avisar cuando el usuario pulsa algún botón; **nunca lee ni escribe archivos JSON directamente**.

---

## 2. Diseño visual, estados y guía de estilos

La estructura de la tarjeta sigue este esquema:

```text
+---------------------------------------------------------------------------+
| [Icono Cat.]  Cena Supermercado Mercadona               [ 48,50 € ]       |
|               Pagado por: Jesús · 22/11/2026            [ PENDIENTE ]     |
|                                                    [✓ Saldar] [✎] [🗑]   |
+---------------------------------------------------------------------------+
```

Para mantener la misma línea gráfica que ya usamos en los sprints anteriores de **PayClear**:
* **Tipografías:** `Manrope` en negrita (`15pt` / `16pt`) para el título del gasto y el importe, y `DM Sans` (`12pt`) para el pagador, la fecha y la etiqueta de estado.
* **Iconos:** Iconos vectoriales `.svg` cargados con `FlatSVGIcon` (`20x20 px` para la categoría a la izquierda y `16x16 px` para los botones de acción).

### Estados visuales de la tarjeta

| Estado | Aspecto visual (FlatLaf) | Cuándo se activa |
| :--- | :--- | :--- |
| **Normal (Pendiente)** | Borde gris claro (`1px solid #D0D7DE`, esquinas redondeadas `arc: 12`), fondo blanco `#FFFFFF` y etiqueta ámbar `#FFF8C5`. | Estado por defecto cuando el gasto aún no se ha liquidado. |
| **Hover** | Borde verde `#38B28B`, fondo `#F6FFFA` y cursor en forma de mano (`HAND_CURSOR`). | Al pasar el ratón por encima de la tarjeta. |
| **Seleccionado** | Borde morado más marcado (`2px solid #3C2A96`) y fondo `#EEEDFF`. | Cuando el usuario hace clic sobre la tarjeta para ver su detalle (`selected = true`). |
| **Saldado** | Borde verde `#38B28B`, fondo verde suave `#E6F7EE` y etiqueta verde `#1A7F37`. | Cuando el gasto ya está pagado/liquidado (`settled = true`). |
| **Deshabilitado** | Fondo gris `#F3F4F6` y botones internos bloqueados. | Mientras se está guardando o sincronizando en segundo plano (`enabled = false`). |

## 3. API pública y requisitos JavaBean

Para que el componente se pueda arrastrar e integrar sin errores en editores visuales de Swing/Matisse, cumple las reglas del patrón **JavaBean**: clase pública, serializable, **constructor público sin parámetros**, propiedades privadas con valores por defecto y métodos `getters` y `setters` públicos.

### Constructores
* `public ExpenseCardPanel()` — **Constructor vacío obligatorio** (inicializa la tarjeta con los valores por defecto).
* `public ExpenseCardPanel(String expenseId, String title, double amount, String payerName, String dateText, boolean settled)` — Constructor completo para instanciarla rápido desde código.

### Propiedades, valores por defecto y métodos accesores

| Propiedad | Tipo | Valor por defecto | Métodos públicos | Qué actualiza en pantalla |
| :--- | :--- | :--- | :--- | :--- |
| `expenseId` | `String` | `""` | `getExpenseId()` / `setExpenseId(String)` | ID interno del gasto (no se muestra al usuario). |
| `title` | `String` | `"Nuevo gasto"` | `getTitle()` / `setTitle(String)` | Texto principal con el concepto del gasto. |
| `amount` | `double` | `0.00` | `getAmount()` / `setAmount(double)` | Importe formateado en euros (`0,00 €`). |
| `payerName` | `String` | `"Sin asignar"` | `getPayerName()` / `setPayerName(String)` | Texto `Pagado por: <nombre>`. |
| `dateText` | `String` | `"--/--/----"` | `getDateText()` / `setDateText(String)` | Fecha del gasto junto al pagador. |
| `category` | `String` | `"GENERAL"` | `getCategory()` / `setCategory(String)` | Cambia el icono SVG de la izquierda según categoría. |
| `settled` | `boolean` | `false` | `isSettled()` / `setSettled(boolean)` | Cambia la tarjeta entre *Pendiente* y *Saldado*. |
| `selected` | `boolean` | `false` | `isSelected()` / `setSelected(boolean)` | Activa o quita el borde morado de selección. |
| `accentColor` | `Color` | `new Color(56, 178, 139)` | `getAccentColor()` / `setAccentColor(Color)` | Color de acento del componente. |

## 4. Cómo se comunica con el resto de la app (Eventos)

Para no mezclar la interfaz gráfica con la lógica de datos, la tarjeta avisa de lo que hace el usuario mediante la interfaz `com.payclear.ui.events.ExpenseCardListener`:

```java
package com.payclear.ui.events;

import java.util.EventListener;

public interface ExpenseCardListener extends EventListener {
    void onCardSelected(String expenseId);
    void onSettleToggled(String expenseId, boolean newSettledState);
    void onEditRequested(String expenseId);
    void onDeleteRequested(String expenseId);
}
```

La clase `ExpenseCardPanel` incluirá estos dos métodos para registrar o quitar escuchadores:
* `public void addExpenseCardListener(ExpenseCardListener listener)`
* `public void removeExpenseCardListener(ExpenseCardListener listener)`

## 5. Criterios de aceptación (para las pruebas de `T-3.5`)

El componente se dará por válido cuando pase estas comprobaciones (que servirán de base para los tests de JUnit 5):

1. **CA-01 (Constructor vacío):** Al hacer `new ExpenseCardPanel()`, la tarjeta se crea sin lanzar excepciones y muestra sus valores por defecto (`"Nuevo gasto"`, `0,00 €`, pendiente).
2. **CA-02 (Actualización de propiedades):** Al llamar a cualquier `setter` (por ejemplo, `setTitle` o `setAmount`), el texto o estilo de la tarjeta cambia al instante y lanza el `PropertyChangeEvent` correspondiente.
3. **CA-03 (Control de importes negativos):** Si se intenta pasar un importe menor que `0` en `setAmount`, se deja en `0.00` o se lanza una `IllegalArgumentException` controlada sin romper la vista.
4. **CA-04 (Botón Saldar):** Al pulsar el botón de saldar, cambia el valor de `isSettled()` y se ejecuta `onSettleToggled` en todos los *listeners* conectados.
5. **CA-05 (Botones Editar y Eliminar):** Al pulsar editar o eliminar, se dispara una sola vez `onEditRequested` u `onDeleteRequested` pasando el `expenseId` correcto.
6. **CA-06 (Estado deshabilitado):** Si `setEnabled(false)` está activo, los botones dejan de responder y no se lanza ningún evento al hacer clic.
